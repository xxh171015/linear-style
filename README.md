# Linear local replica

以已安装的 Linear 1.32.8 为参考的 React／Electron 复刻，提供离线模式和可选的本机账号服务。包含任务与关联关系／关联创建、可恢复删除、分诊、迭代、项目、计划、视图、收件箱、评审、Agent 和 Loops。完整 1:1 对齐尚未验收通过；已观察、已实现和待验证项分别记录在[对齐清单](docs/research/linear-parity/README.md)与[视觉验收](design-qa.md)。

## 运行

需要 Node.js 和 pnpm。

```sh
pnpm install
pnpm dev --host 127.0.0.1 --port 5174
```

打开 <http://127.0.0.1:5174/>。初次启动使用示例数据；后续从当前浏览器的 IndexedDB 恢复。更换浏览器、地址或端口会使用不同的本地存储。

在 Settings 中导出备份后可移至其他浏览器，再通过导入预览恢复。备份包含任务、关联记录、附件内容、草稿、会话和运行历史。请保管备份中的本地内容。

常用操作：`C` 创建任务，`⌘/Ctrl K` 命令菜单，`J/K` 移动列表选择，`Space` 预览，`Enter` 打开详情，`Esc` 关闭浮层。帮助菜单列出已实现的快捷键。

在任务详情中按 `Shift H` 或选择 Issue options → Remind me 设置提醒。支持快捷时间、自选日期及 `in 2 hours` 等时间输入；待提醒记录位于 Snoozed，到期进入 Inbox。重新打开提醒可取消。应用关闭时不发送系统提醒，重开后可查看到期记录。

## 桌面版

桌面版当前使用离线存储，不连接下面的账号服务。

需要 Node.js 22.12 或更新版本。运行 `pnpm desktop` 可构建并启动独立桌面应用；`pnpm desktop:package` 生成当前系统的应用包。macOS arm64 产物位于 `artifacts/desktop/Linear Replica-darwin-arm64/Linear Replica.app`。

`pnpm desktop:smoke` 使用临时数据目录检查桌面本地页面加载与工作区就绪，不复用已打开应用的工作区；额外传入 `--smoke-two-windows` 可验证两个窗口的就绪与保存退出回执。开发时先运行浏览器预览，再运行 `pnpm desktop:dev`。

桌面版数据与浏览器存储分开，通过 Settings 导出／导入备份迁移。包含原生菜单、窗口装饰、Dock 未读徽标与保存后关闭；支持新建窗口及同一来源内的共享保存；并发同字段修改会提示冲突。已实现可选择启用的桌面通知、标签独立历史和窗口／标签恢复；系统通知实际送达及原生重开尚待可视验收。自动更新和发布签名仍待实现。

## 验证

```sh
pnpm test
pnpm build
```

当前 222 项测试通过，生产构建包含前端和服务端 TypeScript 检查。浏览器验收覆盖创建、复制草稿与副本保存、任务提醒到期／取消、任务链接／关联文档与项目移动、分诊、状态切换、跨页面联动、刷新恢复、附件、视图、评审、会话、自动化及备份恢复，以及账号注册／登录／退出、双页服务端同步、服务中断后的保存重试、邀请码加入、跨账号任务编辑和最后一位管理员保护。

## 账号版

在本机 Node.js 26.13.0 验证。运行 `pnpm server:start` 构建并启动服务，打开 <http://127.0.0.1:4175/> 创建 Replica 账号。已有构建可运行 `pnpm run server`。这是复刻应用自己的账号，不使用原版 Linear 登录凭证。默认仅监听本机，没有公开发布。

每个账号创建自己的工作区，也可通过邀请加入其他账号的工作区。不同账号可以在同一工作区共同编辑任务和项目；同一账号的多个登录会话共享保存。工作区与附件、加盐密码摘要及会话保存在 `.replica-server/workspaces.sqlite`，该目录已忽略提交。备份此目录时应先停止服务，保留完整数据库及可能存在的 WAL 文件。可用 `REPLICA_DATABASE`、`REPLICA_PORT`、`REPLICA_HOST`、`REPLICA_PUBLIC_ORIGIN` 配置运行位置；本轮没有部署远程主机。

账号工作区初始为空。从离线版 Settings 导出备份，再在账号版 Settings 导入可迁移记录。账号版支持服务端版本检查、冲突提示、事件推送和断线后的保存重试；断线期间未保存的修改仍在当前页面内存中，刷新前需保存或导出备份。账号过期可在 Settings 选择 Reconnect account。不同会话预留任务编号，避免并发创建冲突，因此编号可能不连续。

工作区菜单提供 Invite and manage members 和 Switch workspace；Settings → Members 可搜索、排序、导出成员列表，创建／撤销邀请，管理 Admin／Member 角色及移除成员。邀请有效期七天：管理员将仅显示一次的邀请码交给收件人，收件人以被邀请邮箱注册或登录本服务器，在 Settings 输入邀请码加入。服务不会发送邮件，也不把未验证邮箱单独当成身份凭据；邀请码仅保存摘要、接受一次后失效。最后一位管理员不能被降级或移除。

草稿、收藏、收件箱、任务订阅、聊天、显示偏好及草稿／聊天附件按账号隔离；任务、项目、文档及已发布的关联附件由工作区成员共享。其他成员修改已订阅任务后，通知进入订阅者自己的收件箱。撤销成员会终止其事件连接并拒绝后续读取与保存；已下载的副本无法收回。切换工作区前须保存，失败时可以导出备份，或明确选择放弃本窗口未保存修改。

多团队管理、细粒度权限／访客、业务记录中从显示名称迁移到成员 ID、邮件验证和密码重置、桌面版连接账号服务、后台自动化与真实 AI 仍待实现。上述服务端实现是本地复刻设计，未恢复或复用 Linear 私有服务端代码。

## 离线边界

运行此项目不会访问原版账号。原版观察和少量原版检查记录的创建／清理单独记在对齐清单。离线模式将记录保存在本机；账号模式保存至自行运行的 Replica 服务。账号模式已支持跨账号共享工作区与 Admin／Member 权限，团队层级和细粒度权限仍待完成。

Agent 使用确定性的本地查询、摘要和待确认草稿；不调用 AI 模型。评审使用本地记录，不读取 GitHub 或执行合并。Loops 通过独立适配层执行受支持的本地动作；Slack 和 coding session 标明受限，不产生外部操作。定时任务仅在应用打开时检查，不提供后台调度承诺。

项目进度、容量和部分分诊转换是明确标记的本地规则，未当作已验证的 Linear 服务端规则。任务选项提供相关、父、子及两种阻塞方向的创建入口，任务与关系一起保存；创建表单支持里程碑。任务描述、评论和项目说明已支持富文本；已补充项目列表／看板／时间线及日期排期；提及、表格、提示块、折叠块、描述版本恢复、评论线程及表情回应已实现；Settings 可管理任务模板，创建表单可应用模板；独立文档支持项目关联、自动保存和可恢复删除。上述本地功能不等于完整原版对照验收；全部菜单、历史图表和部分高级交互仍待对齐。

## 实现入口

- `src/workspace.ts`：实体仓库、业务命令、迁移和 IndexedDB。
- `src/issue-ui.tsx`：列表、筛选、创建与详情。
- `src/relations.ts`、`src/relation-ui.tsx`：任务关系、阻塞图和关系选择器。
- `src/feature-pages.tsx`：其余模块。
- `src/project-views.tsx`、`src/timeline.ts`：项目列表、看板、时间线和日期排期。
- `src/adapters.ts`、`src/services.ts`：外部能力的离线适配边界。
- `src/replica.css`：界面样式。

可通过任务选项删除本地任务，在团队 Archive 恢复。备份保留已删除记录；当前没有实现原版 30 天后的永久清除。

新的领域约定见 [ADR 0005](docs/adr/0005-reference-parity-and-offline-workspace.md)。截图证据存于本机 `artifacts/qa/`，已忽略提交。
