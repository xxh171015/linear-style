# Account server and shared sessions

The original goal remains a complete, verified reconstruction of Linear's core functions. The offline boundary in ADR 0005 is no longer the sole persistence mode. Existing REA artifact evidence (`ev_a563070e76a5b48f1c5d640753a0355e680a16e77a2d6f0cecf7c352994a5ea4`, ASAR SHA-256 `5f13f9e9784b1c5a13b761ec50657879408084e8f8ee91fbfb3c6b1aa80b0dd8`) does not provide Linear's private account service implementation. This server is an independently implemented reconstruction layer, not recovered backend code or verified authentication-flow parity.

The optional browser server owns accounts, salted scrypt password hashes, hashed session tokens and SQLite workspace snapshots. A session cookie is HttpOnly, SameSite Strict and expires after seven days; HTTPS origins use Secure. Mutations require the app's custom request header and matching Origin when supplied. SQL uses parameters. API reads and writes validate the authenticated account’s membership of the selected workspace; account or workspace headers never grant access on their own. The default listener is loopback. No hosted deployment was performed.

Each account creates one workspace and can join others. The legacy `workspaces.user_id` key remains its stable workspace ID; `workspace_members` relates authenticated user IDs to Admin or Member roles. Independent accounts and sessions share the existing three-way merge and explicit conflict flow. SQLite revision compare-and-swap rejects stale snapshots; the client retries independent concurrent changes. Attachment bytes share the backup wire format and undergo workspace validation. A 32 MB JSON request limit bounds snapshot transfers. SSE revisions and periodic recovery reads keep browser sessions current. A revision event carries no task content.

Repositories bind to both the account and workspace identities returned by the authenticated service. The server checks this binding on subsequent requests. If another tab changes the shared cookie to a different account, the old window cannot read that account's workspace or upload its retained changes into it. An older server that omits account identity is refused rather than treated as compatible.

Issue identifiers are reserved in atomic blocks of 16 per repository session. Reservations account for already-imported issue IDs and are durable across restarts; concurrent new issues therefore do not accidentally claim the same identifier. Unused reservations can leave numbering gaps. This allocation policy is a reconstruction choice, not an observed Linear rule.

Offline IndexedDB storage and Electron remain available independently. Browser bootstrap uses the account gate only when an account API is actually present; Electron keeps its existing offline mode. There is no silent upload or replacement of the user's existing offline workspace. Moving data requires export and explicit import through Settings.

Failed writes retain changes in memory and expose retry/export. Failed background reads expose a sync warning. Reauthentication is tied to the current account email and preserves the mounted workspace. Signing out requires pending writes to finish. Pending changes are not journaled to disk in account mode; the app does not claim recoverability after closing or refreshing while unsaved.

Admin-only endpoints create/revoke invitations, change roles, remove members and rename workspaces. The server protects the last admin. Invitations bind to the addressed email and require a separate random one-use code provided by the admin; only a SHA-256 digest is stored, and the code is not exposed through pending-invitation lists. This avoids treating unverified email registration as proof of invitation ownership. There is no email delivery. Invites expire after seven days; a replacement invalidates the old code. Legacy invitations without a code are invalidated during migration. These policies are independent reconstruction choices, not recovered Linear rules.

Private snapshots hold drafts, favorites, inbox/read state, chats, preferences, task subscriptions and draft/chat attachments per `(workspace_id,user_id)`. Shared snapshots hold tasks, projects, documents, published entity attachments and other workspace records. Public snapshots project the current account name and subscription flags. Updating an issue sends new activity notifications to other subscribing members’ private inboxes within the same SQLite transaction. Global workspace revisions serialize both private and shared writes, allowing the existing merge logic to preserve independent changes. A revoked member’s private data stays inaccessible and retained for a possible later invitation. Revocation closes their live streams immediately and the API checks membership on every subsequent read/write/reservation.

A member can switch between accessible workspaces only after pending writes finish. Failed writes require a backup/save decision; discarding is explicit. Restored tabs are cleared on account/workspace switch. A stale tab cannot upload to a new account or a different workspace. The browser UI keeps offline and account stores separate.

Still required: multiple teams within a workspace, fine-grained permissions/guests, migrating business-record actor/assignee fields from display names to stable member IDs (duplicate display names remain ambiguous), email verification/reset, desktop connection configuration, server-owned background schedules, hosted integration and AI adapters, and source-matched UI/behavior verification. These are not replaced by tests of the narrower collaboration layer.
