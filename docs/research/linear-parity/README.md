继续落实此前 REA 的 openNewWindow 桥接声明。本轮新增 File → New window（⌘/Ctrl Shift N）及桌面命令菜单入口，每个窗口拥有独立路由／标签页和独立关闭保存回执。菜单操作发送给当前窗口；IPC 校验调用来源属于相应主框架。退出应用时先收齐全部窗口的保存回执，任何窗口失败都保留窗口供用户处理，不会把首个回执误当作全部保存完成。

共享存储不再无条件覆盖整份快照：先读取共享版本，按共同基础合并字段／ID 集合，再在 IndexedDB 读写事务中核对版本并提交。事务发现版本变化则重新读取、合并；已通过事务的修改不会被旧快照悄悄覆盖。首次打开工作区也在事务中确定同一份初始数据，避免两个新窗口各自生成默认时间和数据。

本地规则：不同对象和不同字段的写入自动合并；同一字段的不同值保留为显式冲突，失败写入不修改数据库，本地未保存快照仍可导出。用户可选择保留自己的冲突值（仍保留共享侧其他字段），或重新加载共享快照（界面明确说明会丢弃当前未保存改动）。相同任务编号的并发新建不能强行覆盖，需保留备份、重新载入后重新创建；尚未重建原版服务端的全局编号分配。附件相等性使用内容摘要，避免同尺寸不同内容被误认为相同。合并结果再次经过现有导入验证，双向阻塞等跨对象矛盾会整次拒绝。

各窗口通过 BroadcastChannel 和聚焦时读取同步已保存快照；正在保存／有未解决错误时不以远端快照覆盖本地未保存修改。后台自动化通过同源 Web Locks 只在一个页面运行，保存出错时不继续自动执行；缺少该能力的浏览器只在聚焦页面检查。修正详情页未编辑的标题、标签和描述未跟随共享更新的问题，防止失焦写回旧标题。已在编辑中的局部表单内容继续保留；全套表单的跨窗口编辑冲突规则尚未与原版逐项验证。
